# Handoff — 2026-11-09

## 13:13:24 -06:00 — Crossfade direction follows the audible deck

**Symptom (user report):** Deck A was playing; the user pressed Play on Deck B (still silent, since
the crossfader sat on A) and then hit Auto crossfade. The direction flipped to B → A and the fade
pulled B in and back out instead of moving A → B.

**Cause:** `resolveSourceDeck()` in `src/stores/mixer.js` trusted `activeDeck` whenever that deck was
playing. Pressing Play on B set `activeDeck = 'B'` while the crossfader kept B at volume 0, so the
silent deck became the source. `autoCrossfade()` then snapped the fader onto B (`crossfader = 1`),
making the silent deck jump to full volume before fading it out. The direction strip and the
timed-fade cue used the same active-deck-first rule.

**Fix:** new pure helper `crossfadeSourceDeck({ activeDeck, crossfader, decks })` in
`src/lib/crossfade.js`: with both decks playing it returns the louder crossfader side; with one
playing it returns that deck; at an exact 50/50 split it returns `activeDeck`; with none playing it
returns `null`. `resolveSourceDeck` keeps the previous item/queue fallbacks for stopped decks and now
wraps it; `livePlayingDeck`, the panel's `liveDeckId`, and the "Next crossfade" direction use the same
helper, so preview, timed cue and actual fade always agree.

**Where:** `src/lib/crossfade.js`, `src/stores/mixer.js`, `src/components/CrossfaderPanel.vue`,
`src/lib/crossfade.test.js`, `src/App.smoke.test.js`, ODD S4 + L18.

**Evidence:** RED first — 5 new unit tests failed with `crossfadeSourceDeck is not a function`, and
the new smoke test (play A, play B, fader on A) asserted `source: 'A'` but got `'B'`. After the fix,
129/129 tests green and `vite build` clean (148.33 kB JS). The direction-strip test was updated: it
plays B and stays A → B, then moves the fader onto B and flips to B → A.

**State:** the change is not committed yet; `git status` shows the five source/test files plus the
two docs touched.
